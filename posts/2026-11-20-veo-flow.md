在尝试用大模型生成超过单次时长上限的视频时，最容易遇到两个现实问题：**分段视频拼接处画面跳变严重**，以及**生成耗时长、前端误点或轮询重试导致的高额 API 重复扣费**。

为了把零散的脚本收敛成真正顺手的创作工具，我做了 [veo-flow](https://github.com/suakitsu/veo-flow) —— 一套基于 Google Veo 3.1 原生 SDK（`google-genai` 1.x+）与 FFmpeg 的 AI 视频生成工作台。

## 为什么分段生成的视频总是“接不上”

单次文生视频往往只有几秒。如果直接拿第二段提示词重新生成，人物站位、光影色温和镜头运动方向都会重置，硬切在一起会有很强的割裂感。

在 `veo-flow` 中，我把长视频生成拆成了三条可组合的帧级流水线：

1. **尾帧自动提取与续接（Frame-to-Frame Continuation）**：上一镜头生成完毕后，后端调用 FFmpeg 精确抽取最后一帧高清 PNG 作为下一镜头的起始参考帧（Initial Image），让光影、构图与主体材质自然延续。
2. **首尾帧关键帧插值（First-Last Frame Interpolation）**：在已知转场起点与终点的场景下，同时传入首帧与尾帧约束镜头运动轨迹。
3. **原生视频延展（Native Video Extension）**：结合 Veo 3.1 原生延长接口，在保持运动惯性的前提下向后扩展时间轴。

```python
# 提取上一段视频尾帧作为下一段生成的起始参考帧
def extract_last_frame(video_path: str, output_image_path: str) -> str:
    cmd = [
        "ffmpeg", "-y",
        "-sseof", "-0.05",
        "-i", video_path,
        "-frames:v", "1",
        "-q:v", "2",
        output_image_path
    ]
    subprocess.run(cmd, check=True, capture_output=True)
    return output_image_path
```

## 自动配音与长文本切分流水线

只有画面没有旁白的视频在创作场景里依然是半成品。`veo-flow` 在 `routes/narration.py` 中集成了双引擎旁白工作流：

- **Gemini TTS**：支持 30 种音色与 70+ 语言，适合多语种解说；
- **MiMo TTS**：针对中文长文本单次合成上限，自动按标点与语义边界切分段落，分段合成后再用 FFmpeg 无缝拼接并对齐视频轨道时长。

> 当旁白时长与视频画面时长不一致时，系统会自动计算音频轨与视频轨的差值，按配置选择留白淡出或智能对齐，避免台词被生硬截断。

## 生产级防呆：单 IP 任务锁与生成前成本预估

视频生成模型的单次调用成本远高于普通文本模型，而且一次生成往往需要数十秒到数分钟。如果不做并发限制和成本提示，页面刷新或连点两次按钮就意味着双倍账单。

为此我在 `services/task_manager.py` 和路由层加了三道保护：

| 保护机制 | 实现位置 | 解决的问题 |
| --- | --- | --- |
| **生成前费用预估** | `routes/generate.py` | 按所选模型（Veo 3.1 / Veo 3 / Imagen 4）、分辨率与秒数实时换算预估开销，确认后再下发请求 |
| **单 IP 并发任务锁** | `services/task_manager.py` | 同一客户端存在未完成的长耗时任务时拒绝重复提交，并通过 SSE 推送当前任务进度 |
| **路径安全与 XFF 校验** | `services/file_security.py` | 严格校验上传参考图的 MIME 与文件名，防止路径穿越与伪造 `X-Forwarded-For` 绕过锁机制 |

```text
veo-flow/
├── app.py                  # Flask 应用入口与 Blueprint 注册
├── generators/             # Veo 3.1 / Imagen 4 / 客户端封装
├── routes/                 # 视频生成、TTS 配音、SSE 任务流与 OpenAPI 文档
├── services/               # 任务锁、历史记录、指数退避重试与文件安全校验
└── docker-compose.yml      # Gunicorn + Gevent 生产容器编排
```

## 小结

把模型能力包装成 Demo 很容易，但要让它在日常创作中真正好用，核心往往在于**上下文衔接（尾帧提取与音画同步）**和**工程边界保护（任务锁、SSE 状态恢复与账单预估）**。完整源码与 OpenAPI 规范已开源在 [suakitsu/veo-flow](https://github.com/suakitsu/veo-flow)。
